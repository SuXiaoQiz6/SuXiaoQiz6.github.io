产品笔记

记录怎么把需求收成可做的范围：先想清楚给谁用、不做什么、错了怎么办。下面是目前整理好的一条完整案例。

01 独立原型 Vibe Coding

VideoHub

把 B 站、抖音、YouTube 的公开链接，收成一条本机链路：解析 → 预览 → 保存到本地。

角色
自己写 PRD 并落地
形态
本机网页原型
范围
只做能跑通的 P0
材料
GitHub 仓库

问题

想把公开课或收藏视频存到本地时，各平台入口不统一：有的没有下载，有的缓存格式难用，合集还要一条条处理。

目标用户很具体：在 B 站 / 抖音 / YouTube 看到一套课程，只想勾选其中几集，离线看。

产品目标

第一版只回答三件事：链接能否解析、文件能否保存、合集能否勾选后批量下载。

网页端先做完；付费视频、去水印、会员体系都放到后面。

关键决策

作品集里真正要看的，是做了什么、以及明确不做的。

  1. 下载交给浏览器下载栏 不自建应用内任务队列。第一版先保证「能保存」，状态机留到 P1。
  2. 预览和下载拆开 预览走代理流，下载走附件。预览失败时仍应能下；返回首页只取消预览，不断已开始的下载。
  3. 不把导 Cookie 做成产品步骤 B 站公开视频尽量免登录。未登录清晰度常见上限约 720p，更高档位不承诺。
  4. 合集至少保留一条勾选 取消全选时，回到「当前正在看的那一集」，不允许全部空选。查看详情不改已选项。
  5. 首页不放 X 入口 后端仍能解析公开原生视频，但演示入口不放，避免面试时被无关内容带偏。
  6. 改一个平台，不能打挂另一个 B 站 / 抖音 / YouTube 解析路径隔离。这是 vibe coding 时最容易翻车的地方，所以写进红线。

这一版做了

  • 粘贴链接解析：B 站、抖音短链、YouTube
  • 浏览器里预览，再交给 Chrome / Edge / 夸克下载栏
  • 合集分页、勾选、全选规则、多任务下载
  • 先写 PRD 和阶段性补充需求，再按验收口径收口

明确没做

  • 账号、Stripe、去水印
  • 应用内下载队列和进度面板
  • 登录后的高码率与音视频分轨合并
  • 公网部署（解析必须有独立后端）

怎么验收

  • 公开单稿：解析 → 预览 → 下载
  • 合集：勾选 N 条，下载栏出现 N 个任务，文件名可用
  • 返回首页：预览停，下载继续
  • 刷新媒体页：还能回到当次解析结果

局限

这是个人 vibe coding 原型，给学习和面试演示用，不是上线产品。请只解析自己有权访问的公开内容，并遵守各平台条款。

没有真实用户量和留存数据。YouTube / X 受平台风控，失败是预期，不把它写成「登录 VideoHub」。

02 笔记

企业采购大模型 API 时在选什么

销售侧选型笔记。信息来自公开资料与顾问实践，不是厂商评测。

问题

企业常说「要上大模型 / 要私有化」，真正卡住的是：场景成不成立、数据能不能出域、账单能不能控、效果能不能接受。

做法

先给结论，再用场景矩阵决定主推 / 备选 / 不推，并写清价格口径与客户顾虑。材料截图待补。
