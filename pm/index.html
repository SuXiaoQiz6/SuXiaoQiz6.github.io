产品笔记

从产品需求出发，分析用户场景与产品目标，设计产品功能与产品页面，vibe coding一步步纠正落地细节。

01 独立原型 Vibe Coding

VideoHub

把 B 站、抖音、YouTube 等音视频平台的公开媒体学习资源解析，提供给用户统一的资源预览与本地保存体验，方便用户提高学习效率。

角色
自己写 PRD 并落地
产品形态
本机网页原型
材料
GitHub 仓库

问题

想把公开课或收藏视频存到本地时，各平台入口不统一：有的没有下载，有的缓存格式受平台约束，合集还要一条条处理。

目标用户很具体：在 B 站 / 抖音 / YouTube 看到一套课程，想缓存其中几集，离线观看。

产品目标

第一版只做成三件事：链接能否解析、文件能否保存、合集能否勾选后批量下载。

网页端先做完；付费视频、去水印、会员体系都放到后面。

产品运行

同一条课程链接走完三步。图按实际界面贴，点开可看原图。

  1. 01

    预览加载

    解析成功后先进入媒体页。预览还在拉时写明「正在加载」，标题、来源和合集已经在下面，不让页面空着。

  2. 02

    视频播放

    用浏览器原生播放器预览。清晰度、来源和时长跟在播放器下面，合集入口不挡正在看的这一集。

  3. 03

    多集下载

    勾选 P1、P2、P3 后，下载按钮显示数量。浏览器下载栏同时出现三个文件，而不是合成一个。

关键决策

做了什么、以及明确不做的。

  1. 初版下载交给浏览器下载栏 不自建任务队列。第一版优先保证「能下载保存」，状态机留到 P1。
  2. 预览和下载拆开 预览走代理流，下载走附件。预览失败时仍应能下载；返回首页只取消预览，不会中断已开始的下载。
  3. 合集至少保留一条勾选逻辑 取消全选时，回到「当前正在看的那一集」，不允许全部空选。查看详情不改已选项。
  4. 各平台解析任务隔离 基于产品主要目标，以及不同平台的视频类型和用户目的，隔离不同平台的解析与下载任务，提高效率。

这一版做了

  • 粘贴链接解析：B 站、抖音分享短链、YouTube、X
  • 预览视频，再交给 Chrome / Edge / 夸克下载栏
  • 合集分页、勾选、全选规则、合集视频下载
  • 先写 PRD ，再按验收标准监督AI作业

后续补充

  • 账号、Stripe体系、去水印
  • 应用内下载队列和进度面板
  • 登录后的高码率与音视频分轨合并
  • 公网部署

怎么验收

  • 单个视频：解析 → 预览 → 下载
  • 合集：勾选 N 条，下载栏出现 N 个任务供用户确定保存路径后下载
  • 返回首页：预览停，下载继续
  • 刷新媒体页：预览效果重新加载

局限

这是个人 vibe coding 原型，目前仅支持本地clone项目运行，不是上线产品。另外该工具仅供个人学习使用，请只解析自己有权访问的公开内容，并遵守各平台条款。

02 独立原型 RAG · Vibe Coding

KnowledgeHub

面向虚构机加工企业「北湾机电」的本地知识库问答：管理员管理已发布知识库文档，员工可按照权限提问，回答要么带可追溯引用，要么明确标成「非制度依据」。

角色
自己定义场景与边界并落地
产品形态
本地前后端原型
场景设定
制造业工厂包含制度 / 安全 / 质量 / 设备四类知识库
材料
本地仓库 · 截图待补

问题

制度、安全规范、质量文件分散在各处时，员工常靠口头打听。答错有代价，答不出来也要说清楚「这不是制度原文」。

产品目标

两条主流程：管理员上传并发布知识库文档并可通过普通员工测试账号测试问答效果；员工在有权限访问范围内提问，可看到正常命中回答，无命中时显示无依据提示，保证严谨性

产品仅作为缩小版 ToB AI知识库问答系统，基本逻辑包括知识库建设链路闭环、权限隔离、引用回答等核心功能

关键决策

先SQLite+BM25+本地ollama+qwen2.5本地逻辑跑通，不绑定商业向量库，后续再部署云端及升级技术架构

文档切块逻辑与Topk选择要从语义级别定义，减少命中丢失概率

MVP先不做管理员的文档切块设置，缩小测试与任务量

  1. 无出处回答逻辑 分成三类：有可靠命中带引用；主题相关但无可靠原文 → 一般性回答 +「非制度依据」；完全无关 → 短答并引导改问知识库主题。`refused` 表示没有企业引用，不是不说话。
  2. 弱命中不挂假引用 分数够才抢救成抽取式 grounded；否则走 ungrounded，citations 必须为空。
  3. 检索用 BM25，不用默认 Embedding 先证明「免费本地可跑通」。口语漏检靠标题锚定和短文档兄弟块，不维护「几点→时间」这类词表。
  4. 权限停在知识库级 用户组 → 知识库 `can_read`。MVP 不做单篇文档 ACL；员工默认搜全部有权库，管理员可切单库测检索。
  5. 只用自写虚构样本 12 份原创制度 / 安全 / 质量 / 设备文档。不粘贴国标或付费模板，也不冒充真实客户 POC。
  6. 未发布的知识不进检索 上传 → 解析分块 → 发布为当前版本后才可问到。草稿与解析失败版本对员工不可见。

MVP原型包括

  • 工号登录、角色隔离；员工进不了管理端
  • 知识库文档上传、解析、发布 / 取消发布
  • 员工问答：答案依据抽屉、三类无依据策略、会话历史
  • 赞踩反馈 API；可选 Ollama 生成，未配也能抽取式演示

明确没做 / 半截

  • 创建知识库 API、单篇 ACL、版本浏览页
  • 用户组 CRUD、反馈列表、问答统计：多为骨架
  • 默认 Embedding / 商业向量库 / 公网 Online Demo
  • 多轮对话进 prompt（会话可续，生成仍按本轮检索）

怎么验收

  • 问车间穿戴要求 → grounded，能打开原文
  • 问旋转机床能否戴手套 → 应命中禁止类条文，不被 ungrounded 抢走
  • 问「1+1」→ 无答案依据，并引导知识库范围
  • 草稿未发布 → 员工问不到；发布后可问到

局限

虚构企业演示用原型，不是真实客户交付。管理端部分入口仍是骨架；登录页旧文案与「三类无依据」行为尚未完全对齐。产品运行截图与公开仓库待补。
